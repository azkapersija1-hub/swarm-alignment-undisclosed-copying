# DEVIATIONS from the stage-1 declarations (all made BEFORE any fresh data were scored or inspected)

Found by an independent code review of the analysis code (2026-11-08). No monitor output on D1/D2/D3 had been looked at when these were made; the only data viewed were the pilot (non-confirmatory seeds), synthetic fixtures and D0 (exploratory, contaminated).

| # | Change | Reason | Effect on numbers |
|---|---|---|---|
| 1 | Bootstrap unit is the SOURCE DOCUMENT of agent A (not the pair replicate x document); same for the F31 gate clusters and the H6 median-difference interval | Replicates reuse one corpus, so the same document in different replicates is not independent; the stage-1 wording gave too-narrow intervals | Wider, more conservative intervals |
| 2 | Per-record seed for the frozen formulas' random draws is a SHA-256 hash of (scenario id, replicate) | The v1 code used hex()[:8] of the id, which is the same 4 characters ("cali" or "test") for every row of a split, so all rows of a split shared one random stream. This is also a defect of the ORIGINAL study | Small changes in STP-AR, RCC and MOI baseline values; the v2 baselines are not bit-identical to the v1 baselines |
| 3 | ARG-H7 reference set excludes every calibration centroid identical to one of the row's own report centroids, not only those of the same scenario | Honest reports are reused across scenarios; leaving byte-identical copies in the reference set made calibration scores differ in distribution from test scores | Changes H7 only |
| 4 | Paired comparisons (F31 gate, ARG-H10 accuracy) refuse to run unless both monitors cover the same rows in the same order; refit-bootstrap resamples are used for all monitors or none | Positional misalignment could pair unrelated rows without an error | None if no replicate was dropped; otherwise the comparison is reported as not computed |
| 5 | A falsifier whose inputs contain NaN is reported as undetermined (null), never as "not falsified"; a missing mode counts as undetermined | NaN comparisons evaluate to False | Can only turn a false "not falsified" into "undetermined" |
| 6 | Cross-arm transfer restricts fit rows, per test replicate, to domains that are calibration domains of that test replicate | Domain splits are redrawn per replicate, so a document could be a calibration row of the fit arm and a test row of the test arm | Fewer fit rows, no document overlap |
| 7 | Only a missing LLM monitor yields a missing part in a per-replicate fit; any other KeyError aborts | A typo or a missing field must not silently shorten a monitor's pool | None |
| 8 | Track 2 excludes the whole trial if any agent failed, and only domains with at least four base sources are used | A failed upstream agent hands empty text downstream and biases the propagation rate downward | Reported as n_trials_excluded_failed_agent |
| 9 | score_v2 refuses a run file whose record count differs from the expected 244 (164 for D0); outputs are written to a temporary file and replaced | A truncated file at a line boundary would otherwise be scored silently | None |

NOT changed, on purpose:
- The independence-claim regex (IC) stays as declared in stage 1. A reviewer noted it can misfire (for example "I did not consult other analysts; my evidence is independent"). Its agreement with the design label (only SHARED_OK discloses non-independence) is reported in audit.json (ic_regex_design_agreement) so the effect on ARG-H8 is visible.
- The legacy ledger monitors (P, F10) keep the v1 semantics for the old modes (comm_hidden and half_mcar are treated as visible logs), as declared. They are not comparable to ARG-H8's anchored L_known.
- controller_v2.py and gen_v2.py are unchanged since the stage-1 lock (a reviewer's note that controller_v2 writes its run file non-atomically is handled by the record-count check in item 9).

## Tooling change after the stage-2 lock (before any D1/D2/D3 scoring)
10. score_v2.py gained an optional `--cache` argument (separate embedding-cache file per concurrent process, so parallel scoring jobs cannot overwrite each other's cache). No effect on any number. Stage 2 was re-locked (see PREREG_LOCK_STAGE2.json, later timestamp) before the first scoring run.
11. score_v2.py llm_row: an LLM-monitor call that raises (HTTP 429 from the shared Gemma endpoint under concurrent load crashed three scoring processes) is retried up to 8 times with growing pauses; if it still fails the row gets NaN scores with llm_parse_fail and llm_error flags, which the audit reports. No effect on any number where calls succeed. The crashed jobs wrote no score files; stage 2 was re-locked before any D1/D2/D3 scoring succeeded.

## Resource change after the stage-2 lock (before any D1/D2/D3 evaluation; not outcome-driven)
12. The Gemma cloud endpoint (gemma4:31b-cloud) returned HTTP 429 persistently from about 10:00 local on 2026-11-08 (account quota exhausted, confirmed by the owner; Qwen via Token Plan kept working). Consequences, decided without looking at any D1/D2/D3 result: (a) the LLM monitors F0b and D are computed with `tp:qwen3.8-flash` ONLY in every arm (the declared pair gemma4:31b-cloud + tp:qwen3.8-flash is reduced to its second member; rep0 score files written before the quota ran out also hold Gemma LLM columns, which are ignored by `--llm-monitors tp:qwen3.8-flash`); (b) Track 1 (red-team, board) and Track 2 conditions that need Gemma as an agent are not run again: the Qwen/DeepSeek/mixed versions already run are the only Track 1-2 results; (c) agent generation for all arms was finished before the quota ran out, so the generated data are unaffected. Effect: the LLM-monitor baseline is a Qwen monitor, not a Gemma monitor; the monitor and the agent are therefore never the same model in the Gemma-agent arm D1, and are the same model family in D2-Qwen (disclosed under the R2 untrusted-monitoring note).
